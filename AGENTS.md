# AGENTS.md

## Основные указания

Отвечай как опытный технический напарник. Не объясняй очевидные вещи, не пиши воду и общие рассуждения.

Всегда отвечай на русском языке.

## Назначение проекта

Проект представляет собой простой веб-чат в реальном времени на WebSocket.

Основной сценарий работы:

1. Пользователь регистрируется.
2. Пользователь входит в аккаунт.
3. После авторизации пользователь попадает в общий чат.
4. Пользователи обмениваются сообщениями через WebSocket.
5. Все сообщения сохраняются в базе данных.
6. История сообщений может загружается из базы данных.

## Важный контекст

Это небольшой проект без сложной бизнес-логики. Не усложняй архитектуру без необходимости. Предпочитай простые и понятные решения вместо избыточных абстракций, паттернов и микросервисного подхода. Если задачу можно решить простым способом — выбирай простой способ.

Перед добавлением новых сущностей, слоев абстракции, библиотек или сервисов сначала оцени, можно ли решить задачу существующими средствами проекта.

## Структура проекта

Перед любыми изменениями изучи:

* README.md — описание проекта и сценарии использования;
* docker-compose.yaml — состав сервисов и инфраструктуры;
* src/ — весь исходный код проекта.

Перед написанием нового кода обязательно изучай существующие реализации и придерживайся уже используемых паттернов. Также изучи документы в директории .codex/ перед началом работы. В директории .codex/tasks/ будут находиться задачи, которые необходимо будет выполнить.

## Правила работы

Если не хватает информации для выполнения задачи, сначала задай уточняющие вопросы, а не делай предположения.

Перед внесением изменений:

1. Изучи существующую реализацию.
2. Найди похожие функции, классы или модули.
3. Следуй текущему стилю проекта.
4. Не создавай новую архитектуру, если аналогичная уже существует.

Если задача крупная:

1. Сначала предложи план.
2. Дождись подтверждения.
3. После этого приступай к реализации.

Если информация в AGENTS.md противоречит информации в файлах из .codex/*,
уведоми о противоречии и запроси уточнение. До получения уточнения не делай предположений.

* не дублируй существующую логику.

## Команды

Управление зависимостями осуществляется через Poetry.

Основные команды:

- poetry install
- poetry add <package_name>
- poetry remove <package_name>
- poetry run \<command>
