## Задание

Сейчас в проекте реализована базовая авторизация по логину и паролю. Необходимо расширить её, добавив дополнительный биометрический фактор - верификацию по ручной подписи. Пользователь после ввода пароля должен будет подтвердить личность, расписавшись на графическом планшете.

Что нужно анализировать:
- Нормализованные координаты подписи: Центрирование, масштабирование и сглаживание;
- Нажим пера: Показатели силы нажатия в разные моменты времени;
- Угол наклона пера: Показатели наклона пера в разные моменты времени;
- Время соприкосновения: Общая длительность касаний;
- Количество разрывов: Число отрывов пера от поверхности графического планшета.

Цель: Повысить безопасность авторизации за счёт двухфакторной схемы.

## Начальные условия

Будем считать, что авторизация по паролю + подпись для всех пользователей устанавливается по умолчанию. Т.е. при регистрации сразу просить пользователя ввести пароль, подтвердить его и 5 раз ввести подпись на графическом планшете, который способен определять степень нажима пера и угол наклона пера. Графический планшет всегда будет использоваться один и тот же и будет гарантированно снимать указанные характеристики.

## flow регистрации и авторизации

Регистрация: login + password + 5 samples подписи
- создание user;
- создание эталонного шаблона подписи;
- регистрация завершена.

Авторизация: login + password + подпись
- backend првоеряет пароль;
- backend оценивает подпись с эталоном;
- success: выдает токены;
- fail: возвращает ошибку, frontend кидает на login.

## Нормализация

Перед сохранением эталона и перед DTW необходимо:

1. Найти bounding box подписи
2. Сдвинуть подпись в центр
3. Масштабировать до общего размера
4. Сохранить пропорции
5. Сгладить мелкий шум

## Хранение эталона в БД

Эталонный вариант подписи будет рассчитываться, как среднее значение по 5 samples, которые были введены при регистрации. Т.е. это будет таблица со связью 1 к 1 с таблицей пользователей, которая будет хранить массивы с усредненными значениями координат, наклона пера, длительности проставления подписи, количеством отрывов пера.

## Алгоритм сравнения подписей

DTW в проекте использовать как основной алгоритм сравнения динамической подписи. Он будет сравнивать эталонную последовательность координат/нажима/наклона с текущей последовательностью координат/нажима/наклона и возвращать расстояние. Чем расстояние меньше, тем подписи более схожи. Дальше необходимо расстояние превращать в score и сравнивать с пороговым значением.
