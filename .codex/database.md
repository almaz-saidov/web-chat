# database.md

## База данных

Проект использует PostgreSQL и SQLAlchemy ORM.

Основные сущности:

- User — пользователь системы;
- Message — сообщение в общем чате;
- RefreshToken — refresh-токен пользователя.

---

## Таблица users

Хранит зарегистрированных пользователей.

| Поле          | Тип                      | Описание                    |
| ------------- | ------------------------ | --------------------------- |
| id            | UUID                     | Первичный ключ              |
| username      | VARCHAR(50)              | Уникальное имя пользователя |
| password_hash | VARCHAR(128)             | Хэш пароля                  |
| created_at    | TIMESTAMP WITH TIME ZONE | Дата регистрации            |

### Ограничения

- username должен быть уникальным;
- пароль хранится только в виде хэша;
- удаление пользователя удаляет связанные записи через CASCADE.

---

## Таблица messages

Хранит сообщения общего чата.

| Поле       | Тип                      | Описание        |
| ---------- | ------------------------ | --------------- |
| id         | UUID                     | Первичный ключ  |
| user_id    | UUID                     | Автор сообщения |
| content    | TEXT                     | Текст сообщения |
| created_at | TIMESTAMP WITH TIME ZONE | Время отправки  |

### Связи

- Message -> User (Many-to-One)

Каждое сообщение принадлежит одному пользователю.

При удалении пользователя все его сообщения удаляются автоматически.

---

## Таблица refresh_tokens

Хранит refresh-токены для обновления JWT.

| Поле          | Тип                      | Описание                 |
| ------------- | ------------------------ | ------------------------ |
| id            | INTEGER                  | Первичный ключ           |
| user_id       | UUID                     | Владелец токена          |
| refresh_token | UUID                     | Уникальный refresh-токен |
| created_at    | TIMESTAMP WITH TIME ZONE | Дата создания записи     |
| expires_at    | TIMESTAMP WITH TIME ZONE | Дата истечения токена    |

### Ограничения

* refresh_token должен быть уникальным;
* один пользователь может иметь несколько refresh-токенов;
* при удалении пользователя все связанные refresh-токены удаляются автоматически.

### Назначение

Refresh-токены используются для получения новой пары access/refresh токенов без повторной авторизации пользователя.

---

## Схема связей

User (1)

├── Message (N)

└── RefreshToken (N)

Один пользователь может иметь множество сообщений и множество refresh-токенов.

---

## Миграции

Любое изменение ORM-моделей должно сопровождаться созданием миграции Alembic с понятным **message**.

Команда:

```bash
poetry run alembic revision --autogenerate -m "<message>"
```

После создания миграции необходимо проверить её содержимое на корректность. Не изменять структуру таблиц без создания соответствующей миграции.

## Правила работы с БД

- использовать SQLAlchemy ORM;
- использовать UUID в качестве первичных ключей (кроме RefreshToken.id -> INTEGER);
- не хранить пароли в открытом виде;
- использовать внешние ключи для связей между таблицами;
- не дублировать данные между таблицами без необходимости;
- при удалении пользователя связанные данные должны удаляться через CASCADE.
